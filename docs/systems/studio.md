# Character Studio

The drawing/animation/effects editor page.
Moved out of CLAUDE.md (2026-10-17). Keep this file up to date when the system changes.

A second page for DRAWING how heroes, enemies and minions look (pixel-art `parts`, anchors, `height`, `hover`): `studio.html` + `src/studio/main.js`, for WIDESCREEN only (user's choice; no phone layout): the live preview is pinned on the left, a Draw / Animate switch in the header picks what fills the rest.
- DRAW SCREEN LAYOUT (session 35, from the mock `docs/proposals/studio-ui/mock-draw.png`): LEFT column = Preview card (stage; one row: animation drop-down `#anim-pick` + play `#replay` + Arena + zoom `#zoom-pick` + speed `#speed-pick`; Mirror in its title bar), PARTS list (`renderParts()`: a 28 px picture of each part `drawThumb()`, ↑ / ↓ `data-move`, and a ⋯ `data-menu` button that opens the part pop-up `#part-menu` holding `#editor`: name, position, anchor, clear, flip / turn / outline, copy to, idle wiggle, Copy part, Delete part), WHOLE CHARACTER (health bar / flies-at sliders, Swap colour toggle row, Versions drop-down, Trace…, Undo unsaved, Back to game). RIGHT = one vertical tool strip `.toolstrip` (tools, then mirror drawing, undo, redo) + the board card `.boardcard` filling the rest of the screen height (sticky): above the board the tool's name and ONLY its options (`data-opt="rect ellipse"` etc., toggled in `setTool()`), Dim other parts, board zoom; under it one colour strip (current colour + this character's colours + starter). `fitBoard()` sizes the canvas to fit its box (ResizeObserver), board zoom multiplies that. Long help = the header `?` pop-up `#help-pop`; tool hints are tooltips. Parts / Whole character hide in Animate and Line-up. Animate = a TIMELINE (`src/studio/timeline.js`: clip tabs; a clip the character does not have yet opens as the game's BUILT-IN motion written as keyframes (`defaultClip()` in animClips.js) and becomes the character's own on the first change; "Reset to built-in" throws it away; a layer per part with X / Y / Rotation keyframe rows, playhead, play, scrub labels, drag diamonds, ease per key; dragging a part in the preview adds X/Y keys) and a drawing board (`src/studio/board.js`: pencil, eraser, line, rectangle, ellipse, fill, shade, colour picker, anchor, move, undo/redo; drawing outside a part grows it, erasing its edges shrinks it) and the game's own `Character` class for the live preview (Idle / Swing / Walk / Skill / Hit flash, Mirror, zoom, tap to pick a part).
- SECTIONS (header tabs): UNITS (heroes, enemies, minions), ITEMS (item icons) and EFFECTS (`src/studio/effects.js`, `EffectsEditor`): every effect of the game (76: status loops, hits, shots, item effects, skill effects) plays live with the game's OWN recipe code on a small stage at game size (Knight vs Goblin + Slime, plain canvas); per effect a SPEED slider (0.25x-3x) and its colours as swatches (tap one to replace that colour everywhere in the effect); Reset to game; Save effect = db collection `effects`, doc `<group>-<name>` `{ kind: 'effect', group, name, speed, colors }` (localStorage when local). The game reads `src/data/effects.json` (groups status / hit / shot / item / skill) through `src/systems/fxTune.js` (`makeTuner()`: `speed`, `ms`, `paint`, `color`; `statusLook(..., tune)`, `BattleScene.addFx(ms, fn, [group, name])`, impacts, shots, tornado). Tests: `fx-tune.test.mjs`. `setSection()` in main.js filters the picker and the line-up. Unsaved drafts are kept per browser only for EDITED characters, with a fingerprint of the game look they were drawn over (`-draft2`); old-style drafts are set aside under `soldia-studio-designs-draft-old`.
- PREVIEW extras: SPEED 1x / ½x / ¼x (slow motion: the studio scene gives Character its own clock, `scene.clipNow()` -> `Character.now()`, and scales tweens/timers), ARENA play button (a mini fight at game size, Goblin vs a hero or Knight vs an enemy: walk, 3 swings, hit-back, skill, death every 2nd round, using the same timings; `StudioScene.prototype.arena`).
- TIMELINE extras: ONION SKIN (red/green ghosts of the pose `onionGap` ms before/after the playhead), the HIT marker on the Attack clip (`hitAt` in the clip: the game stretches the clip so that moment lands with the hit, `Character.swing()`), Copy key / Paste key (onto the selected layer at the playhead), "Copy this clip to…" another character (only layers with matching part names), eases `back` (overshoot) and `bounce`.
- PART TOOLS (part card): Flip ↔ / Flip ↕ / Turn 90° / Add outline (dark 1-px outline) via `transformPart()` (board.js) and the grid helpers in pixelArt.js (`flipGridH/V`, `rotateGrid90`, `outlineGrid`, `replaceColorGrid`; the anchor moves with the pixels), "Copy part to…" another character (replaces a same-named part). WHOLE CHARACTER: "Swap a colour" (every pixel of one colour, all parts, becomes the current colour). TRACING IMAGE (board card): a picture from the device shown faintly behind the grid, strength slider, kept in localStorage. LINE-UP mode (header): every character's standing pose at game size on the floor, with unsaved changes (plain canvas, `drawLineup()`).
- SAVED VERSIONS: every Save also keeps the design as an older version (db collection `history`, doc `<key>--<time>`, newest 15 per character; localStorage when local); the Whole character card lists them ("Load a saved version", loads as unsaved changes, Undo works). The card also says which characters are saved but NOT in the game yet (saved look differs from the game JSON).
- ELLIPSE tool (key O, `ellipseCells()` in board.js): drag corner to corner, a square box = circle; "Filled shapes" fills it (and the rectangle). SHADE brush (key D): rub over drawn pixels to make each one step darker (Shift held or "Shade lightens" = lighter), once per pixel per stroke; `shadeColor()` / `SHADE` in pixelArt.js (darker leans purple, lighter leans cream). Tests in `pixel-art.test.mjs`.
- SELECT tool (key V): drag a box over the selected part, drag inside it to move those pixels ("Copy when moving a selection" leaves the originals), Delete / "Clear selection" empties it, Esc lets go (`selectDown/selectUp/clearSelection` in board.js). BOARD ZOOM: − / 100% / + buttons and two-finger pinch on the board (iPad), 100% to 400%, the board scrolls inside `.boardwrap`.
- MIRROR DRAWING (toolbar button / key S, remembered in localStorage): everything drawn on the board (pencil, eraser, line, rectangle, fill) is also drawn mirrored across the character's middle line x = 0 (pixel column c <-> -1-c, `mirrorCell()` in board.js), into the same selected part; a dashed blue line shows the middle.
- iPad gestures (like Procreate, in main.js): two-finger tap = undo, three-finger tap = redo (quick tap, no sliding; the first finger's half-started stroke/drag is thrown away with `cancelEdit()`, which also gives back the redo list), touch and hold with a FINGER on the drawing board = pick that colour (the Apple Pencil keeps drawing); a small toast says what happened. The board ignores non-primary pointers.
- Build: `npm run build:studio` (makes `studio-page.html`), copy it to the scratchpad as `soldia-studio.html`, publish to the SAME url https://claude.ai/artifact/1azV1LBUimRkeavNpQBgc7 (declares the `db` capability; omit `capabilities` on republish to keep it).
- Saving: the "Save design" button writes to the page's database, collection `designs`, doc id `hero-<id>` / `enemy-<id>` / `minion-<id>` (`{kind, id, name, height, hover?, parts, savedAt}`); saved effects go to collection `effects`. When the user says "apply the studio designs": read BOTH collections with ArtifactData (`list`, collections `designs` and `effects`), write them together as one JSON list to a scratch file, run `node scripts/apply-designs.mjs <file>` (only changes parts/height/hover, and effect speed/colours in effects.json), run tests, check the game in the browser, commit, republish the game.
