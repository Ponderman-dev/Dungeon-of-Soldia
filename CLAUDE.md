# Dungeon of Soldia

Mobile auto-battler roguelike. Phaser 3 + Vite + plain JavaScript (ES modules, no TypeScript).
Will be wrapped for Android later (Solana Seeker dApp Store).
Full design: `docs/game-design-recap.md`. Read it before designing features.
BIG UPDATE in progress: `docs/big-update-plan.md` (plan + BUILD ORDER, phases A-H) and `docs/item-list.md` (all 72 items). Follow the build order one step at a time.

## About the user
Total beginner, fully vibe coding. Explain simply, work in small steps,
and ask before big decisions (new libraries, big refactors, design changes).

## Rules
- **Screen:** portrait 390x844 (see `src/config.js`). Crisp pixel scaling:
  `pixelArt: true`, `roundPixels: true`, Scale.FIT. Never use smoothing/antialiasing on art.
- **Data in JSON:** heroes, items, skills, enemies etc. live in `src/data/*.json`.
  Never hard-code that data inside scene code; scenes only read it.
- **Placeholder art only:** characters are colored blocks built from separate parts
  (body, head, weapon) so real pixel-art parts can replace each one later. No real art yet.
- **Git:** commit after every working step, with a clear message. Don't commit broken code.
- **Small steps:** do one step at a time, then stop and tell the user how to see it.

## Fight rules (decided)
All numbers below go in JSON/config so they are easy to tune.
- **Damage types:** physical (melee, ranged) and magical (fire, ice, electric, dark). Every attack and skill has one type.
- **Defense:** % cut of PHYSICAL damage. No hard cap: a curve (`armorPercent()` in combat.js, `armorCurve.linearUpTo` 50 in combat.json): up to 50 points 1 point = 1% (10 defense = 10% less), above that each point is worth less and the cut never reaches 100% (75 def = about 70%, 100 = about 82%).
- **Resist:** same curve as defense, for MAGICAL damage. Heroes have 7 stats in use (mana is off).
- **Weak/resist per enemy:** each enemy lists `weak` and `resists` damage types in JSON (weak = +50% damage, resists = -50%). A list can also name a whole category ("physical", "magical").
- **Damage-type bonuses** (e.g. +15% dark) also boost damage over time of that type (the bonus is baked into the DoT when it is applied). `validateDamageTypes()` checks every damage type named in the JSON (run at start, and in `damage-types.test.mjs`).
- **Melee vs ranged:** melee attacks CAN hit flying enemies but miss 40% of the time (`meleeVsFlyingMissPercent` in combat.json). Ranged has no penalty. No formation rules yet.
- **Evasion:** % chance to fully dodge a hit of any type, capped at 70% (`caps.evasion`).
- **Crit:** % chance to deal 2x damage, capped at 100% (`caps.crit`).
- **Attack efficiency:** attack speed. 100 = 1 attack per second.
- **Attack timing:** a basic attack STARTS (`attackStart` event: attacker, target, `hitInMs`) and LANDS later (`attack` event). Delay = combat.json `attackTiming` per side (`hero` / `enemy`: `swingMs` 220 for melee, `rangedHitMs` 260 for arrows; 0 = instant). The walk to the target is NOT part of the delay (see MOVEMENT): a melee fighter only starts its swing once it stands next to its target. If an arrow's target dies meanwhile it bends AT ONCE to a new target (`attackRetarget`, at least `retargetMinMs` 200); a melee swing whose target dies is lost (`attackCancel` 'noTarget') and the fighter stays ready and walks to its next target. If the attacker is stunned/frozen/feared/knocked back meanwhile the attack is cancelled (`attackCancel`). Skills and item hits keep the small lunge (only from a fighter's own spot). The delay doesn't change attack speed. Tests: `attack-timing.test.mjs`, `movement-edge.test.mjs`.
- **No mana (for now):** mana is switched off. Skills run on COOLDOWN ONLY. The `mana` stat/growth in heroes.json, `manaCost` in skills.json and the mana rules in combat.json are dormant (nothing reads them).
- **Healing:** each hero heals 25% of max health after a win (bigger after bosses).
- **Squad of 3:** a run has 3 heroes (`squad.json`: Knight, Rogue, Archer; the other 7 heroes stay in `heroes.json` as the bench; `pickSquad()` in `src/systems/party.js`). No boxes behind the hero slots any more; name, perk line and skill squares sit under each hero.
- **Hero perks (party buffs, decided by the user one by one):** each hero has a `perk` in heroes.json (`mods` shaped like item effects: `stat` + `percent`/`flat`, or a `special` + `percent` such as skillDamage/regen/dotDamage; plus `growth` per level). While that hero is ALIVE the whole party gets it (the hero too). Knight Stalwart +8 defense and +5% max health, Rogue Shadow Step +10 evasion, Archer Marksman +8% attack speed, Berserker Battle Fury +10% attack, Samurai Bushido +8 crit, Mage Arcane Haste +10% skill damage, Cleric Blessing +0.4% health regen per second (fights only), Necromancer Grim Resolve +8 resist, Bard Inspiration +6 evasion, Alchemist Volatile Mix +10% damage over time (`dotDamage`, applies to DoTs the hero's side puts on enemies). A dead hero's perk is lost. Shown as e.g. "Team +8 DEF +5% HP" under the hero name ("perk lost" when dead).
- **Morale:** when heroes fall the living ones get a permanent (for the run) debuff, in combat.json `morale`: INCOMPLETE (one hero down, 3 of 3 becomes 2 alive): -10% attack, -10% attack speed, -3 defense, -3 resist. ALL ALONE (one hero left): -25% attack, -25% attack speed, -8 defense, -8 resist. Shown as a faint colour wash over every living hero (no text, no popup): light purple = INCOMPLETE, darker = ALL ALONE (`tint` / `tintAmount` in combat.json `morale`, `Character.setWash()`, `BattleScene.drawMoraleWash()`); `morale` event from `BattleState.killUnit`. Tests: `party.test.mjs`.
- **Dead heroes:** stay dead for the rest of the run. Run ends when all 3 are dead.
- **Tap-to-focus:** all heroes attack the tapped enemy until it dies (melee heroes walk to it wherever it is), then go back to auto-target. Auto-target: RANGED heroes pick a RANDOM living enemy on every attack; MELEE heroes keep their opponent (`foe`) until it dies, then take the NEAREST enemy (by lane, `BattleState.nearest()`). Single-target skills with no tapped enemy use the same pick.
- **MOVEMENT (rebuilt, Warcraft-3 style, user's drawing):** positions live in the RULES, not the scene. Every fighter has `x, y` (its feet, screen pixels) once `BattleState.place()` was called (the scene does it in `startFighting()`; tests/bot use `placeLines()` with `movement.layout`). Every update (`BattleState.move()`): a MELEE fighter walks straight at its target at `movement.walkSpeedPxPerSec` (170) until the target is inside its reach oval (`reachX` 64 sideways, `reachY` 94 up/down), then swings; both sides walk so two melee fighters meet in the middle, face to face. RANGED fighters stay where they are and shoot. Fighters closer than the `separateX/Y` oval push apart (`separatePushPerSec`; ranged ones hold their ground), so a crowd spreads around a target instead of stacking. Feared = walks back to its own spot; knocked back = pushed `knockbackPx` towards its own side over `knockbackMs`; stunned/frozen or mid-swing = stands still. Nobody can move faster than walking + pushing, so no teleporting or sliding. The scene only DRAWS: `followPositions()` puts each figure at its position every frame, with a hop per step while `moving` (`attackMotion.hopHeight` / `hopLengthPx`, rhythm from `walked`); lower heroes are drawn in front. FACING: every fighter is mirrored left/right to look at whoever it fights (its swing target, its opponent, or the last thing it shot at; `Character.face()`, the art looks the way its weapon part points); heroes look the normal way again after a win. HEALTH BARS are always drawn on top of every character: enemy bars/tags slide in with their floor, then leave the floor container in `startFighting()` and get the `heroBar` depth. Targets: enemies keep their opponent, a new one is the NEAREST hero by real distance (`nearest()`); melee heroes likewise; ranged heroes pick at random; tap-focus wins. After a win heroes walk back to their slots at walking speed. Without positions (some rule tests) nobody moves and melee can always hit. Tests: `movement.test.mjs` (walk, meet, speed, ranged stay, no teleport, no stacking, retarget, fear, knockback, targets).
- **Levelling:** heroes gain XP from kills (`xp` per enemy in enemies.json). An enemy's XP is SPLIT between living heroes; dead heroes are frozen. Needed XP: `xpBase * xpGrowth^(level-1)` (leveling.json). Each hero has its own `growthPercent` (% of base per level: health, attack, mana) and `growthFlat` (points per level: defense, resist, evasion, crit, attackEfficiency) in heroes.json. On level-up, max health rises and current health rises by the same amount. Levels reset every run.
- **Skills:** each hero has ONE attack skill and ONE support skill (`skills: { attack, support }` in heroes.json; every skill in skills.json has `kind` attack/support; `validateHeroSkills()` checks it). Slot 0 = attack (left square, red), slot 1 = support (right square, green); colours in `SKILL_COLORS` (config.js). The Archer's support is a PLACEHOLDER (Eagle Focus) until his redo (Hunter's Mark). Tap a skill square under the hero to cast. One tap: single-target skills hit the focused enemy, else the hero's usual target. Each skill has a cooldown (cooldowns only run during fights). No mana cost. WIND-UP (C1): a tapped skill goes on cooldown at once and winds up for `castMs` (per skill in skills.json, else combat.json `skillWindUp.defaultCastMs` 700, longer than a swing): `castStart` event, the skill name pops up and a charge bar in the skill colour fills under the hero's health bar; then it goes off (`cast`, targets picked at that moment). While winding up the hero does not attack, walk or start another skill. Stunned, frozen or silenced during the wind-up = the skill is LOST and STAYS on cooldown (user's choice; `castCancel`, 'Interrupted!'). Tests: `skill-windup.test.mjs`. SKILL LOOK (C2, combat.json `skillFx`): when a skill goes off the caster flashes in the skill colour (attack orange, support green), a ring bursts on each target (attack) or around the caster (support), the skill name shows as a big banner, skill damage numbers are bigger, orange and pop in; attack skills shake the screen and freeze the fight for a split second (hit-stop). `BattleScene.skillBurst()`. SKILL ANIMATION: heroes use their own pose for skills, not the normal swing (`Character.castWindUp/castRelease/castCancel`): during the wind-up the hero crouches a little and cocks its weapon back; an attack skill then does a big weapon slash with a hop, a support skill a high jump with the weapon lifted; an interrupted wind-up returns to the normal pose. `castLift` is added to the hero's height in `followPositions()`. Skill damage = attack x `damageMultiplier`, uses the skill's `damageType` or the hero's. Targets: `enemy`, `allEnemies`, `self`. Skills can `apply` statuses.
- **Statuses** (rules + tags in `statuses.json`, passed to BattleState as `statusDefs`): stun (can't attack or cast), freeze (same, ice), CHILL (`stacking`: each stack -10% attack speed, at 5 stacks the unit FREEZES for 1.5s and the chill is used up; plain Slow no longer exists), SHOCK (-20% attack speed and 10% chance per attack to fumble = 0.3s stun; refreshes), FEAR (can't attack), KNOCKBACK (`instant`: attack timer restarts, nothing lasting), TAUNT (must attack the unit that taunted it while it lives), SILENCE (can't cast skills; for later enemy skills), stat debuffs (refresh per source, different sources ADD UP; worked out in combat.js `computeDamage`): WEAKEN (-20% attack), ARMOR BREAK (-15 defense, can go below 0 = more damage), CURSE (-15 resist), BLIND (25% of attacks miss), MARK (+15% damage taken, also from damage over time), buff (temporary stat `mods`, same shape as item effects). DAMAGE OVER TIME (`dot`: bleed = physical and ignores defense, burn = fire and ticks every 0.5s, poison = dark): every application adds a STACK with NO limit, each stack has its own timer, all stacks of one kind tick together every `tickMs` as one number (`damageMultiplier` x caster attack per stack, ignores dodge/crit). Other statuses: the same status from the same source refreshes. Enemy `statusDurationScale` (0.5 for bosses) shortens only `control` statuses; DoTs are never shortened. Tags show stack counts ("PSN x3", "CHILL x3"). Tests: `dots.test.mjs`, `control.test.mjs`, `stat-debuffs.test.mjs`. Gambler's Dice crit debuffs: Chill, Poison, Stun or Shock. Hero statuses are cleared when a floor is cleared. Status tags (STUN/SLOW/PSN/BUFF) show by the health bar (`statuses.json`).
- **Shields and Invulnerable (D1):** statuses `shield` and `invulnerable` (statuses.json). ALL health loss from hits, damage over time and thorns goes through `BattleState.dealDamage()`. SHIELD: soaks damage before health, oldest shield first; size = `amount` + `percentMaxHp` of the holder + `attackMultiplier` x the caster's attack; lasts `durationMs`, or until broken if none is given; the same source+skill refills instead of stacking, different sources stack. A shield used up by damage is BROKEN (`shieldBreak` event, optional `onBreak: { damageMultiplier, damageType }` = shards hit every enemy of the holder, damage from the caster's attack); one that just runs out of time EXPIRES (a normal status expire event, no explosion). A hit fully soaked by a shield skips lifesteal, thorns and crit debuffs. INVULNERABLE: no damage at all (hits, DoTs, thorns), `healPercentOnEnd` heals a % of max health when it ends (Divine Shield). Drawn as a thin light-blue bar over the health bar, a "SHIELD 75" tag, "Shield -4" and "Immune!" popups, "Shield broken!" + a small shake. No hero uses them yet (heroes come in phase E). Tests: `shields.test.mjs`.
- **Taunt (D2):** a taunted enemy MUST attack its taunter (`BattleState.tauntedBy()` / `pickTarget()`): melee enemies walk to the taunter, ranged ones shoot it. Taunt beats an enemy's opponent and tap focus rules; when it ends the enemy goes back to its old opponent. The NEWEST living taunter wins (an older taunt takes over again if the newer taunter dies); the same source refreshes. When a taunt lands while an attack is on the way to someone else, a melee swing is dropped (`attackCancel` 'taunted', it walks to the taunter) and an arrow bends to the taunter (`attackRetarget`). Bosses take taunt for half as long (`statusDurationScale`). A proc's status spec can pick its own receiver with `to` (`self` / `squad` / `target`), e.g. the Knight's planned Taunt Wall: one proc with `{ status: 'taunt', to: 'target' }` AND `{ status: 'buff', mods: [defense], to: 'self' }` (taunts the enemy it hit, the Knight alone gets the armor). A thin red line from each taunted enemy to its taunter shows who it is forced to hit. No hero has the passive yet (Knight comes in E1). Tests: `taunt.test.mjs`.
- **"Every Nth attack" counters (D3):** a hero def can have a `counter` (`id, label, color, every` (4), `scope` 'self' | 'squad', `effect` 'empower' | 'heal', `firedLabel`, `strike {damageMultiplier, damageType}`, `apply` [status specs], `forceProcs`, `heal {percentMaxHp, attackMultiplier}`); handled in `BattleState.countBeats()` / `landAttack()`. It counts BASIC attacks that land (not skills, not item hits, not minions): scope 'self' = the holder's own attacks (Mage Spellweaver, Cleric), 'squad' = the attacks of every living hero together (Bard Rhythm). A dead holder counts nothing; the count is kept for the whole run (not reset between floors). On the 4th: EMPOWER = that attack also gets a free extra hit (`strike`) and debuffs (`apply`) on its target, `forceProcs` makes every on-hit item proc of the attacker go off for sure (the Mage); HEAL = the attack heals the lowest-health-% ally instead of hitting (percent of THEIR max health + attackMultiplier x the Cleric's attack), triggers no on-hit items, and if nobody is hurt it hits normally and the counter stays charged until somebody is. Shown ON THE HERO, no text: after the (N-1)th attack the holder's weapon shines with a pulsing orb in the counter colour (`Character.setGlow()`, set in `drawChips()` from `counterCount`), and when the Nth goes off (`beat` event with `fired` and `target`) the attacker flashes in that colour and a big burst (two rings, 8 rays, sparks, small shake) hits the target (around the attacker for a heal beat). No popup text for beats. No hero has a counter yet (they come in phase E). Tests: `counters.test.mjs`.
- **Minions (D4, `minions.json`):** extra fighters on the hero side (`BattleState.minions`, NEVER in `this.heroes`: no XP, perks or morale, never count as living heroes, don't feed counters). Made by SOURCES (`hero.minionSources`, `buildSources()`): the hero's own passive `def.spawner` (Necromancer's Skeleton Summoner: weak, no upkeep) and minion ITEMS the hero holds (items.js effects `minionSpawner` = weak, `greaterMinion: 'id'` = greater; only the holder gets them). WEAK (`{ minion, minMs, maxMs, cap, atFloorStart }`): `startFloor()` (scene calls it when a fight begins) raises the floor-start ones, `tickSpawner()` raises one every minMs..maxMs while enemies live, over the `cap` the OLDEST from that source is pushed out (`minionVanish` 'pushedOut'); each copy of a weak spawner item is its own source; they vanish when the floor is won (`endFloor()` from `onWin`) or their holder dies (`removeMinionsOf()`). GREATER (`kind: 'greater'` in minions.json): ONE per item type, extra copies only make it stronger (`minions.copyStatBonus` 0.5 of its health and attack per extra copy, also if a copy is picked up later); summoned at the start of a fight if there is none; stays between floors with its health (no win heal; only healing/buffs help it); it walks home after a win and through the door with the squad (`livingHeroViews()` includes greater minions, `slotX/slotY`); when it dies it comes back after `minions.revivalFloors` (2) cleared floors, at the start of the floor after that (killed on floor N: floors N and N+1 cleared, back at the start of N+2; `sourceState.wait`, `endFloor()` counts down); it vanishes if its holder dies. UPKEEP (combat.json `minions`): for every minion ITEM of a hero that has a live minion the holder loses 12% attack speed and 12% defense (`upkeepAttackSpeedPercent`/`upkeepDefensePercent`, percent of the level stat, `refreshStats()`), the hero passive costs nothing, upkeep ends when the minions are gone. Minions fight like the other fighters (move, melee/ranged AI, nearest foe; they ignore tap focus), enemies can attack them (`defenders()` = living heroes + minions, nearest wins; taunt works), minion stats are fixed from minions.json (`refreshMinionStats()`; squad-wide buffs reach them via `squadUnits()`, buffs never change their health), statuses and shields work on them. A dying minion: `death` event only (no XP/morale). Scene: `showMinion()` (dark puff + the figure grows out of the floor), `puff()`. No hero or item uses them yet (Necromancer in E8, items in G). Tests: `minions.test.mjs`, `greater-minions.test.mjs`.

## Pixel-art parts (decided)
- Every character part is a small pixel picture: `art: { palette: ["0x..."], rows: ["..01.."] }` (palette index per pixel, "." = empty), `anchor: [ax, ay]` = the turning point inside the picture (0,0 = top-left; 2.5 = middle of the 3rd pixel), `x`/`y` = the picture's middle, `w`/`h` = its size. A part WITHOUT `art` is still drawn as its old block (`w`, `h`, `color`, optional `pivotY`), now as pixels with a dark outline. Helpers: `src/systems/pixelArt.js` (tests: `pixel-art.test.mjs`).
- Animation stays SMOOTH (user choice: pixel sprites, NOT pixel-step animation): `Character.parts[name]` is a pose object (x, y, angle) that tweens move; each part's image copies it every frame (`prerender`) and turns around its anchor. Hit flash = fill tint; morale wash = recoloured texture.

- KEYFRAME CLIPS (`anims` per character, made on the studio TIMELINE): `src/systems/animClips.js` (tests: `anim-clips.test.mjs`). Clips: idle (loop), attack (stretched to the swing time), windup (stretched to the skill's charge time, holds), skillAttack, skillSupport, walk (loop while moving), hurt (on a hit), death (holds). Tracks per part: x, y (pixels, added to the pose) and angle (degrees, turns around the anchor); keys `{ t, v, ease }`, ease = linear / ease / hold. Character plays the most important running clip (death > hurt > attack/skill > walk > idle) on top of the built-in tweens; an action WITHOUT a clip keeps the built-in motion. Battle calls `ch.hurt()` on hits, `ch.die()` on death, `ch.setWalking()` every frame.

## Character Studio
A second page for DRAWING how heroes, enemies and minions look (pixel-art `parts`, anchors, `height`, `hover`): `studio.html` + `src/studio/main.js`, with a TIMELINE (`src/studio/timeline.js`: clip tabs, a layer per part with X / Y / Rotation keyframe rows, playhead, play, scrub labels, drag diamonds, ease per key; dragging a part in the preview adds X/Y keys) and a drawing board (`src/studio/board.js`: pencil, eraser, line, rectangle, fill, colour picker, anchor, move, undo/redo; drawing outside a part grows it, erasing its edges shrinks it) and the game's own `Character` class for the live preview (Idle / Swing / Walk / Skill / Hit flash, Mirror, zoom, tap to pick a part).
- Build: `npm run build:studio` (makes `studio-page.html`), copy it to the scratchpad as `soldia-studio.html`, publish to the SAME url https://claude.ai/artifact/1azV1LBUimRkeavNpQBgc7 (declares the `db` capability; omit `capabilities` on republish to keep it).
- Saving: the "Save design" button writes to the page's database, collection `designs`, doc id `hero-<id>` / `enemy-<id>` / `minion-<id>` (`{kind, id, name, height, hover?, parts, savedAt}`).
